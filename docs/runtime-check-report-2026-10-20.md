## 4. 已确认问题

### 查询历史筛选与分页参数不匹配

前端 `frontend/src/views/query/QueryHistory.vue:173` 至 175 行发送：

```text
page, pageSize, interfaceCode, successFlag
```

后端 `backend/app/api/v1/query.py:49` 至 52 行接收：

```text
page, page_size, interface_code, success_flag
```

后端没有为这些参数声明对应的驼峰别名，导致前端提交的筛选条件和页大小没有进入相应参数。

通过前端代理、携带有效 JWT 执行以下对照请求：

```http
GET /api/query/history?page=1&pageSize=1&interfaceCode=__nonexistent_check__&successFlag=1
```

实测：HTTP 200，`success=true`，`total=79`，`pageSize=20`，返回 20 条。

```http
GET /api/query/history?page=1&page_size=1&interface_code=__nonexistent_check__&success_flag=1
```

实测：HTTP 200，`success=true`，`total=0`，`pageSize=1`，返回 0 条。

影响：选择接口和成功/失败状态后，页面可能仍展示未筛选记录；页面初始配置每页 10 条，但后端默认返回 20 条，使分页展示与实际请求结果不一致。HTTP 200 和 `success=true` 不能证明筛选功能正常。

建议方案（仅建议，未实施）：统一查询参数契约。可以在前端请求层转换为后端的下划线参数，或在后端明确兼容驼峰别名。处理后分别验证接口筛选、成功/失败筛选、页大小及翻页，并检查其他列表接口是否存在同类问题。前端文案写“模糊”，而当前后端接口编码条件使用精确匹配，此语义也需要明确。

### 7.2 新确认问题：文件存储的成功响应无法正确回放或导出

复现对象为已有成功查询记录 `id=81`，接口配置 `id=8`，接口编码 `getBusinessListByDeptOrRegion`。本次仅只读检查该记录，未重新调用上游。

实测证据：

- `GET /api/query/history/81` 返回 HTTP 200，`successFlag=1`、`payloadStoreMode=FILE`、`responsePlain` 为空，`responsePlainSize=495062`。
- `GET /api/query/history/81/structured-view` 返回 HTTP 200、`success=true`，但 `list=[]`、`total=null`。
- 通过记录的落盘路径定位并只读解析对应 `response_plain` 文件，文件存在、大小 495062 字节；使用项目原有 `ResultParserService` 解析可获得 300 条记录，响应中的总数为 604498。
- 对同一记录直接调用现有导出解析函数 `_parse_record_to_list`，结果为 0 条、总数为空。本次未创建导出任务或文件。

604498 仅为该历史响应里的总数，未验证其请求范围、时间和部门层级，不能作为本次“2025 年威海市级所有部门办件量”的结果；300 条也是该历史响应所含记录数，不是全量年度数据。

原因定位：

- `backend/app/services/payload_store_service.py` 在大响应超过阈值时将完整内容落盘，数据库明文字段置空，属于既有存储策略。
- `backend/app/api/v1/query.py` 的 `query_history_structured_view` 只读取 `response_plain_text`，为空时使用空对象，没有读取落盘文件。
- `backend/app/services/export_task_service.py` 的 `_parse_record_to_list` 同样只读取 `response_plain_text`，导致文件型响应进入导出时被解析为空。

影响：成功的大响应会在历史页面被误显示为空；导出解析会丢失这些记录。本次证据证明的是回放接口和导出解析函数异常，未执行下载或实际文件生成验收。

建议方案（本次未实施）：提供明确按 payload 类型读取的统一加载方法，供历史回放、完整报文读取和导出共用；数据库有完整内容时优先读取数据库，否则定位对应的解密文件。文件缺失、JSON 损坏、类型不匹配时应返回明确错误，避免静默生成空结果。针对数据库内联、文件落盘、文件缺失及大响应导出补充回归验证。
